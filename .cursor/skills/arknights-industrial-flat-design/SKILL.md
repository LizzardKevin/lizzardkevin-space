# 工业平面设计合同

> 一句话定义：以黑白灰大色块为结构骨架，以线条 / 条纹 / 网点为工业质感，以警戒色与符号化为功能点缀。形式追随功能 —— 结构表达优先，装饰只服务识别与状态。

## 约束等级

- 将“必须”“仅允许”“禁止”视为验收门槛。
- 任一门槛失败时继续修改；不得以“风格接近”结束任务。
- 按以下优先级解决冲突：功能与可访问性 > 信息层级 > 响应式 > 性能 > 风格装饰。
- 设计交付仅使用规则表、token 表、组件合同、代码和验收清单；禁止背景史、灵感散文和情绪描述。
- 禁止使用“建议”“尽量”“适当”“可考虑”“大概”等软词；存在不确定项时明确写成“假设”或“阻塞项”。

## 适用边界

- 仅修改用户指定的页面、状态和共享组件。
- 保留既有业务逻辑、路由、数据契约、交互语义和测试契约。
- 新界面默认使用暗色工业基底；既有界面存在明确主题契约时保留该契约。
- 只复用设计语法；禁止复制《明日方舟》或鹰角的商标、角色、图标、插画、文案、界面截图、专有纹样和可识别布局。
- 禁止安装字体、图标库、UI 套件或视觉依赖，除非用户明确授权。
- 用户要求实现时必须提交可运行代码；禁止只交付 moodboard、设计说明或伪代码。

## 执行顺序

1. 定位目标页面、所有交互状态、现有 token、字体、组件和测试。
2. 将目标界面压缩为顶栏、主区、侧区、操作区、状态区五类矩形区域；删除无信息职责的区域。
3. 先用黑白灰完成布局和层级；未通过单色检查前禁止添加纹理与警戒色。
4. 建立或复用语义 token；禁止在组件内部散落原始色值和任意尺寸。
5. 完成排版、控件、状态和响应式；最后添加角标、编号、细线、斜纹、网点。
6. 验证默认、hover、focus-visible、active、disabled、loading、empty、error 状态。
7. 运行相关 lint、类型检查和测试；有浏览器能力时检查桌面与移动端截图。

## Token 合同

### 仓库优先映射

| 目标表面 | 必须复用 | 禁止 |
| --- | --- | --- |
| SPACE / 3D HUD | `--space-ink`、`--space-paper`、`--space-metal`、`--space-brand-teal`、`--space-signal`、`--space-hud-surface`、`--space-hud-panel`、`--space-hud-border`（定义于 `spaceVisualTokens.ts`） | 在组件内重复声明同义色 |
| Mobile Terminal | `--terminal-bg`、`--terminal-surface`、`--terminal-text`、`--terminal-muted`、`--terminal-accent`、`--terminal-accent-fill`（另可复用 `--terminal-soft`、`--terminal-accent-ink`、`--terminal-inverse-*`） | 将 `space-*` 与 `terminal-*` 混合进同一组件 |
| 新的独立表面 | 在表面根节点声明下表语义 token 一次 | 全局覆盖既有主题 |

### 独立表面回退值

```css
--industrial-bg: #111315;
--industrial-surface-1: #1b1e21;
--industrial-surface-2: #272b30;
--industrial-text: #f3f0e7;
--industrial-muted: #9aa1a8;
--industrial-line: rgb(243 240 231 / 0.24);
--industrial-accent: #e8d44d;
--industrial-info: #67c2be;
--industrial-signal: #ef8b61;
--industrial-danger: #d85c4a;
```

回退值与仓库 palette 同源（`--industrial-text` = `--space-paper`，`--industrial-info` = `--space-brand-teal`，`--industrial-signal` = `--space-signal`）；禁止把回退值改成与仓库漂移的新色。

- 每个组件文件仅允许引用语义 token。
- 每个表面最多使用 3 个底色层级 + 2 个文字中性色（正文 / 弱化）。
- 中性色必须占可视面积至少 85%；高饱和填充不得超过可视面积 10%。
- 同一屏最多出现 2 个高饱和色族；第二色仅允许表达 error、warning、success 或 info。
- 强调色仅允许用于主 CTA、当前状态、选中项、关键数值和导航定位。
- 禁止用强调色承载正文、长段标题、整屏背景或无语义装饰。
- 红色仅用于错误、危险和破坏性操作；绿色仅用于成功或在线状态。
- 禁止紫色霓虹、彩虹渐变、彩色发光和多色玻璃。
- 仅允许单色明度渐变用于遮罩、晕影或纹理。
- 复古红–黄–青彩条（VHS 意象）仅允许作为活动区块或分区标识的边缘饰条，高度不超过 `4px`，不计入高饱和色族配额；禁止铺底或用作大色块。

## 网格与空间

- 使用 4px 基线；间距仅允许 `4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96px`。
- `>= 1200px` 使用 12 栏；`768–1199px` 使用 8 栏；`< 768px` 使用 4 栏。
- 栏间距：桌面 `24px`；平板与移动端 `16px`。
- 页面边距：桌面至少 `32px`；平板 `24px`；移动端 `16px`。
- 内容边缘必须落在网格线上；禁止肉眼微调产生 `13px`、`19px`、`27px` 等孤立值。
- 每个区域必须至少与另一区域共享一条对齐边。
- 使用非对称布局时必须保留单一主轴；禁止随机错位。
- 用面积、明度和留白建立层级；禁止用大量悬浮卡片建立层级。
- 面板、栏、标签和按钮必须保持矩形。
- 常规圆角仅允许 `0 / 2 / 4px`。
- `50%` 或 `999px` 仅允许头像、状态点、旋钮、拨动开关和明确的胶囊标签。
- 禁止 Bento 卡片墙、营销卡片瀑布流、整页等尺寸圆角卡片。
- 例外：SPACE HUD 与 Mobile Terminal 为密集工具表面，既有尺寸由各自 token 文件定义（如 HUD `rowGapPx: 10`、`heightPx: 36`）；对这些表面做增量扩展时沿用其局部刻度，本条 4px 清单适用于页面级表面与新界面；整体重构既有表面时全量适用本合同。

## 排版

- 每个表面最多使用 3 个字体角色：展示无衬线（重字重大字号）、界面无衬线、数据等宽。
- 优先复用仓库现有字体栈；禁止伪造粗体、伪造斜体和 CSS 拉伸字体。
- 中文正文必须使用 CJK 无衬线字体；代码、编号、时间、坐标、状态码必须使用等宽字体。
- 展示字仅允许用于英雄标题、章节标题和叙事标题；操作标签禁止使用展示字。
- 单个表面最多使用 6 个字号。

仓库字体现状与展示标题解法：

- 界面无衬线：SPACE 使用 `system-ui` 栈；Terminal 使用 `--terminal-font-zh`（PingFang SC / Hiragino / YaHei / Noto）。
- 数据等宽：`--terminal-font-en`（Ubuntu Mono Web，仓库已打包 woff2）或 `"SFMono-Regular", Consolas` 栈。
- 展示标题：本仓库一律使用界面无衬线 + `700` 以上字重 + 大字号（项目决策，禁止使用衬线）；禁止用 `text-shadow` 或 `transform` 伪造字重。

| 角色 | 桌面 | 移动端 | 行高 | 限制 |
| --- | --- | --- | --- | --- |
| Display | `48–96px` | `36–56px` | `0.9–1.05` | 每屏最多 1 个 |
| Page title | `32–48px` | `28–40px` | `1.0–1.15` | 最多 2 行 |
| Section title | `20–28px` | `18–24px` | `1.1–1.25` | 不与正文同字重 |
| Body | `16–18px` | `16–18px` | `1.5–1.75` | 禁止小于 `16px` |
| UI label | `13–16px` | `14–16px` | `1.2–1.4` | 交互控件不得小于 `14px` |
| Data / microcopy | `12–14px` | `12–14px` | `1.2–1.45` | 不承载长文 |

- 未指定字号时使用默认字阶（桌面 / 移动端）：Display `64 / 40`、Page title `40 / 32`、Section `24 / 20`、Body `16 / 16`、Label `14 / 14`、Data `13 / 12`。
- SPACE HUD 的 `12–13px` 字号（`spaceVisualTokens.ts` 的 `hud.fontSizePx` / `panelFontSizePx`）属 Data 角色，不受 Body / Label 下限约束；新增 HUD 元素沿用 HUD token 刻度。
- 字重最多使用 3 档；必须让标题、正文、数据至少跨 2 档。
- 拉丁大写标签最长 24 个字符，字距 `0.08–0.14em`。
- 中文正文禁止增加字距；中文标题字距不得超过 `0.04em`。
- 文本默认左对齐；仅数字表格、坐标和仪表读数允许右对齐。
- 禁止把英文装饰字当作主信息；同一信息必须存在清晰的可读标签。

## 线条、符号与纹理

- 默认边框和分隔线使用 `1px`；激活、选中和焦点结构线使用 `2px`。
- 同一组件仅允许一种默认线宽和一种强调线宽。
- 角标、编号、箭头、三角、刻度、扫描线必须承担分组、状态、方向或进度职责。
- 每个组件最多使用 1 类主符号；禁止叠加三角、准星、条码、网格和警戒带凑风格。
- 图标使用统一的 `1.5px` 或 `2px` 描边；同一表面禁止混用填充图标、表情符号和多套图标风格。
- 条码和 QR 仅允许编码真实数据；装饰场景改用不可误认的抽象扫描条。
- 单屏最多使用 2 类纹理：网点、grain、扫描线、斜纹、晕影中任选。
- 纹理层不透明度不得超过 `0.08`；纹理层必须 `pointer-events: none`。
- 纹理禁止覆盖正文、表单字段、按钮文字和焦点轮廓。
- 优先使用 CSS 或小型 SVG 生成纹理；禁止新增大尺寸栅格纹理。
- 禁止无功能的电线、管线、故障字符、噪点动画和随机 HUD 数字。

## 组件合同

### 面板与卡片

- 用连续色块和分隔线形成分区。
- 卡片必须表达独立对象、可操作记录或明确层级；纯文案分段禁止套卡片。
- 卡片阴影最多使用 2 套固定 token；禁止柔软的大范围营销阴影。
- 面板标题必须包含文本标签；编号只能辅助，不能替代名称。

### 按钮与导航

- 每个面板最多 1 个主按钮。
- 主按钮使用强调色实底；次按钮使用中性色实底或线框；危险按钮仅在危险流程出现。
- 按钮高度桌面至少 `40px`，触屏至少 `44px`。
- 图标按钮的可点击区域至少 `44 × 44px`，并提供可访问名称。
- 当前导航项必须同时使用文本/形状与颜色表达；禁止只靠颜色。
- 禁止将普通按钮做成发光霓虹、玻璃药丸或巨大渐变胶囊。

### 浮层与玻璃

- 毛玻璃仅允许用于 modal、popover、HUD 浮层和固定导航。
- 背景不透明度必须至少 `0.72`；`backdrop-filter: blur()` 仅允许 `8–16px`。
- 浮层必须有 `1px` 边界和明确标题；禁止把所有内容区都做成玻璃。
- 下层内容只保留轮廓，不得与浮层正文形成阅读竞争。

### 表单与状态

- 每个字段必须有持久可见 label；placeholder 禁止替代 label。
- error、warning、success、loading 必须包含文本或图标，禁止只改变颜色。
- disabled 状态必须保持文字可读；禁止仅降低整组件 opacity 到不可读。
- 空状态必须提供下一步动作或原因；禁止只放装饰插画。

### 图片与媒体

- 首屏最多使用 1 个主视觉媒体。
- 媒体必须服从网格并让出主信息和 CTA；禁止拼贴多张大图抢占首屏。
- 必须提供裁切策略、替代文本和加载占位；禁止用背景图承载必要内容。
- 禁止下载或生成近似官方角色、标志、职业图标和专有图形。

## 深度与动效

- 深度仅使用表面明度、`1px` 边界、固定阴影、遮罩和局部模糊表达。
- 动效时长仅允许 `120 / 180 / 240ms`；页面级转场最长 `320ms`。
- 交互动效统一使用 `cubic-bezier(0.2, 0.8, 0.2, 1)`。
- 默认仅动画 `transform` 和 `opacity`；禁止动画布局属性造成重排。
- hover 位移不超过 `4px`；视差位移不超过 `8px`。
- 仅进度、录制、连接和实时状态允许循环动画；其他循环动画禁止。
- 禁止 glitch、频闪、持续扫描、背景粒子雨和无输入自动缩放。
- 必须实现 `prefers-reduced-motion: reduce`；关闭非必要动画并移除视差。
- 例外：既有表面的动效契约保留原值（如 SPACE onboarding 入场 `500ms`）；本表约束新增动效与整体重构。

## 响应式与无障碍

- 移动端按以下顺序保留内容：主任务 > 主操作 > 当前状态 > 导航 > 辅助数据 > 装饰。
- 空间不足时先删除装饰微字、纹理和辅助编号；禁止隐藏主操作与状态。
- 禁止页面级横向滚动；数据表必须使用局部滚动或重排。
- 正文对比度至少 `4.5:1`；大字与非文本 UI 至少 `3:1`。
- `focus-visible` 轮廓至少 `2px`，与相邻颜色至少 `3:1`，不得被裁切。
- 所有交互必须可键盘完成；禁止用 `div` 模拟按钮而不补齐语义和键盘行为。
- 标题层级必须连续；landmark、label、alt 和 live region 必须与功能匹配。
- 在 `320px` 宽度下不得丢失任务、操作和状态信息。

## 性能约束

- 禁止为纯装饰新增 WebGL、Canvas、视频或运行时粒子系统。
- 新增纹理必须使用 CSS 或压缩 SVG；单个装饰 SVG 不得超过 `10KB`。
- 禁止新增字体文件；必须复用现有字体或系统字体栈。
- 首屏装饰不得阻塞主内容渲染；媒体必须声明尺寸以避免布局偏移。
- 禁止为了风格复制同一图标、颜色或阴影实现；必须抽成现有层级允许的 token 或组件。

## 禁止模式

- 紫霓虹赛博朋克。
- 奶油极简和软质黏土感。
- 彩虹渐变、彩色外发光、全屏玻璃。
- 圆角营销卡片瀑布流和 Bento 拼盘。
- 首屏插画堆砌。
- 亮色到处撒。
- 字号和字重无层级。
- 伪终端乱码、无意义坐标、无意义条码。
- 以装饰牺牲可读性、点击面积、性能或响应式。
- 逐像素临摹任何现有游戏或品牌界面。

## 验收门槛

- [ ] 单色截图仍能在 3 秒内识别主任务、主操作和当前状态。
- [ ] 所有新增颜色均来自目标表面的语义 token。
- [ ] 单屏高饱和色族不超过 2 个，且均有功能语义（VHS 边缘饰条除外）。
- [ ] 常规圆角均为 `0 / 2 / 4px`，例外组件符合限定用途。
- [ ] 所有间距均来自 4px 基线清单（HUD / Terminal 局部刻度除外）。
- [ ] 单屏纹理不超过 2 类，各层不透明度不超过 `0.08`，且未覆盖可读内容。
- [ ] 主按钮每面板不超过 1 个。
- [ ] 默认、hover、focus-visible、active、disabled、loading、empty、error 均已检查。
- [ ] `1440 × 900`、`768 × 1024`、`390 × 844`、`320 × 568` 均无任务信息丢失和页面级横向滚动。
- [ ] 键盘操作、对比度、触控面积和 reduced motion 通过。
- [ ] 未引入受保护素材、近似官方图标或可识别的临摹布局。
- [ ] `npm run verify:quick` 通过；改动 SPACE token 时 `node apps/web/tests/space/visual-system.contract-test.mjs` 通过；无法运行的检查必须明确列出原因。
